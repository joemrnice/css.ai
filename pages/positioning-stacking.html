The five position values

ValueBehavior
static (default)Normal document flow. Offset properties (top/left/etc.) do nothing.
relativeStays in normal flow, but offsets shift it visually from where it would have been — and it becomes the positioning context for absolutely-positioned children.
absoluteRemoved from flow entirely; positioned relative to the nearest positioned ancestor (or the initial containing block if none).
fixedRemoved from flow; positioned relative to the viewport, ignores scrolling — unless an ancestor has a transform, filter, or will-change, which creates a new containing block.
stickyActs like relative until a scroll threshold is crossed, then "sticks" like fixed within its parent's bounds.

Offset properties

positioning.css
.dropdown-panel {
  position: absolute;
  top: 100%;   /* just below the trigger */
  right: 0;
}

/* the classic "cover the whole parent" trick */
.overlay {
  position: absolute;
  inset: 0;  /* shorthand for top/right/bottom/left: 0 */
}
The classic bug

An absolute child positions itself relative to the nearest ancestor with a position other than static — forget to add position: relative to the parent, and the child positions against the whole page instead.

position: sticky in depth

sticky needs a threshold — at minimum one of top, bottom, left, or right — or it behaves like relative and never sticks.

  • It sticks within its parent — once the parent scrolls out of view, the sticky child scrolls away with it.
  • A parent with overflow: hidden, scroll, or auto can silently break sticky children — the clipping ancestor becomes the scrolling container.
  • Common use: sticky table headers, sticky section nav, sticky "add to cart" bar.

z-index & stacking contexts

z-index only compares elements within the same stacking context — it is not a single global layering number. A stacking context is created by, among other things: the root element, any positioned element with a z-index other than auto, elements with opacity less than 1, and elements with a transform, filter, or will-change.

Why z-index: 9999 sometimes doesn't work

If a parent creates its own stacking context (say, because it has opacity: 0.99 or a transform for an animation), nothing inside that parent can ever render above a sibling of the parent, no matter how high its z-index goes — it's trapped inside its parent's layer.

stacking.css
.modal-backdrop { position: fixed; inset: 0; z-index: 100; }
.modal          { position: fixed; inset: 0; z-index: 101; }
.toast          { position: fixed; z-index: 200; } /* always above modals */

A maintainable pattern: define a small set of named z-index tiers as custom properties (--z-dropdown, --z-modal, --z-toast) instead of scattering arbitrary numbers across the codebase.

Interview angle

Q: You set z-index: 999 and the element still renders behind another — why? Walk through stacking contexts: check whether an ancestor has opacity < 1, a transform, or its own z-index, which would trap the element in a lower layer regardless of its own z-index value. More in the interview guide.

Syntax & rule anatomy

A CSS rule pairs a selector (what to style) with a declaration block (how to style it). Each declaration is a property: value; pair.

style.css
.card {
  background-color: #12161f;
  border-radius: 10px;
  padding: 1.5rem;
}

/* multiple selectors sharing one block */
h1, h2, h3 {
  font-family: "Space Grotesk", sans-serif;
}

Every declaration ends with a semicolon — the browser is forgiving about the last one in a block, but leaving it off is a common source of copy-paste bugs, so always include it.

Whitespace & case

CSS ignores whitespace between tokens. Property names and keyword values are case-insensitive, but class names, IDs, and URLs are case-sensitive (they're compared like file paths on most systems).

The cascade

"Cascading" is where CSS gets its name. When multiple rules target the same element and the same property, the browser has to pick a winner. It does that in this order:

OrderWhat decides itNotes
1Origin & importanceUser-agent styles → user styles → author styles → author !important → user !important
2Cascade layers (@layer)Later-declared layers win over earlier ones, regardless of specificity, within the same origin
3SpecificityID beats class beats type — see the selectors guide
4Source orderIf everything above ties, the last rule declared wins

In practice: browsers ship default styles (a <h1> is bold and large before you write a line of CSS). Your author styles override those. Within your own styles, specificity and then source order break ties.

Common trap

!important doesn't "turn off" the cascade — it just jumps a declaration to a higher-priority bucket. Two !important declarations on the same property still get resolved by specificity and source order underneath. Overusing it is what makes stylesheets unmaintainable, not the cascade itself.

Inheritance

Some properties automatically pass their computed value down to descendant elements unless overridden — mostly text-related properties like color, font-family, font-size, line-height, and text-align. Box-model properties like margin, padding, border, and width do not inherit — if they did, every nested element would inherit its parent's margin, which would be unusable.

inheritance.css
body {
  color: #1a1a1a;      /* inherits down to every child */
  font-size: 16px;   /* inherits, and % children compute from it */
}

.widget {
  color: inherit;    /* explicitly take the parent's value */
  all: unset;       /* reset everything, then inherit only what you want */
}

Every property also accepts three universal keyword values regardless of whether it normally inherits:

  • inherit — force it to take the parent's computed value.
  • initial — reset to the property's specification-defined default.
  • unset — acts like inherit for naturally-inheriting properties, initial otherwise.
  • revert — roll back to the browser's default (user-agent) stylesheet value.

Units & values

Absolute units

px is the only absolute unit you'll use regularly on screen — 1px is a fixed CSS pixel (not necessarily one physical device pixel). cm, mm, in, pt exist mainly for print stylesheets.

Relative units

UnitRelative toTypical use
%The parent's corresponding dimensionFluid widths, responsive images
emThe element's own font-size (or parent's, for font-size itself)Spacing that should scale with local text size
remThe root (<html>) font-sizePredictable global sizing — the default choice for type scales
vw / vh1% of viewport width / heightFull-bleed sections, hero heights
vmin / vmaxThe smaller / larger of vw or vhSquare elements that scale with the smallest dimension
chThe width of the "0" character in the current fontConstraining text measure, e.g. max-width: 65ch
frA fraction of free space in a grid containerGrid track sizing only
Rule of thumb

Use rem for font sizes and spacing (predictable, respects the user's browser zoom/font settings), % or fr for layout widths, and reach for px only for things that genuinely shouldn't scale — like a 1px hairline border.

Functional values

calc(), min(), max(), and clamp() let you mix units and compute values at run time:

functions.css
.sidebar {
  width: calc(100% - 240px);
}

h1 {
  /* min, preferred, max — fluid type in one line */
  font-size: clamp(1.75rem, 4vw + 1rem, 3.25rem);
}

Ways to apply CSS

  1. External stylesheet — <link rel="stylesheet" href="style.css">. The standard approach: cacheable, keeps markup clean.
  2. Internal <style> — inside <head>. Useful for single-page demos or critical above-the-fold CSS.
  3. Inline style="..." — on the element itself. Highest author specificity short of !important; generally avoided in maintained codebases because it can't be overridden by a class and doesn't cache.
Interview angle

Q: What's the difference between inherit, initial, unset, and revert? Explain that inheritance depends on whether the property is naturally-inheriting, and that unset is context-sensitive between the two. See more in the full interview guide.

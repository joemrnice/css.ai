Frameworks & libraries

Every framework is really a set of decisions someone else made for you. Knowing what decision each one makes is more useful than memorizing class names.

Tailwind CSS

A utility-first framework - instead of shipping pre-built components, it ships a huge set of single-purpose classes (flex, pt-4, text-slate-600) that you compose directly in markup. A build step scans your markup and generates a stylesheet containing only the utilities you actually used.

tailwind-example.html
<button class="px-4 py-2 rounded-md bg-blue-500 text-white hover:bg-blue-600">
  Save changes
</button>

Strengths: no unused CSS ships to production, no naming decisions, design tokens (spacing/color scale) enforced by the config. Trade-offs: verbose markup, a learning curve for the utility vocabulary, requires a build step for the tree-shaking to work.

Bootstrap

A component framework - ships finished, styled components (navbars, cards, modals, forms) plus a 12-column grid system, all customizable through Sass variables. Reach for it when you need to ship a functional UI fast and visual distinctiveness matters less than speed.

bootstrap-example.html
<div class="container">
  <div class="row">
    <div class="col-md-6">...</div>
    <div class="col-md-6">...</div>
  </div>
</div>

Other notable options

LibraryWhat it is
BulmaComponent framework, Flexbox-based, no JavaScript included
Open PropsNot a framework - a curated set of CSS custom properties (spacing, color, shadows, easing) you consume directly, no build step or class vocabulary
Pico CSSClassless framework - style semantic HTML with almost no classes at all, good for content-first sites
UnoCSSAn on-demand, engine-agnostic utility CSS generator - faster build times than Tailwind, compatible syntax

How to pick

  • Design system already exists, need speed - Tailwind, mapped to your tokens.
  • Internal tool, admin panel, prototype - Bootstrap or Bulma, minimal customization.
  • Marketing site that needs a distinctive identity - custom CSS, possibly with Open Props as a token baseline.
  • Content-heavy site, minimal interactivity - a classless framework like Pico.
Interview angle

Q: What are the downsides of a utility-first approach? Verbose, repetitive markup; a real learning curve for the class vocabulary; harder to enforce true one-off visual consistency without disciplined use of the config's design tokens. A strong answer doesn't just praise Tailwind - it names the real cost. More in the interview guide.

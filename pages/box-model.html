The box model

Every element on the page is a rectangular box. Understanding what makes up that box — and which sizing mode you are in — resolves most "why is this 4px off" bugs.

Box anatomy

From the inside out, every box is made of four layers: content, padding, border, and margin.

  • Content — the actual text/image/children, sized by width/height.
  • Padding — space inside the border, same background as the element.
  • Border — a visible (or invisible) edge, sits between padding and margin.
  • Margin — transparent space outside the border, separates the box from its neighbors.
box.css
.box {
  width: 300px;
  padding: 20px;
  border: 4px solid #7aa2f7;
  margin: 16px;
}

box-sizing

This is the single most-asked practical CSS question. By default (content-box), width only sets the content area — padding and border get added on top, so a "300px" box with 20px padding and a 4px border actually occupies 348px.

box-sizing.css
/* the near-universal reset every project should have */
*, *::before, *::after {
  box-sizing: border-box;
}
ValueWhat width measures
content-box (default)Content only — padding & border add to the total rendered size
border-boxContent + padding + border — the box stays exactly the width you set
Why border-box wins

With border-box, a grid of three width: 33.33% cards with padding will actually fit in one row. With content-box the padding pushes the total width over 100% and the third card wraps. This one line prevents a huge class of layout bugs.

Margin collapsing

Vertical margins between block-level, in-flow siblings don't add up — they collapse to the larger of the two. A paragraph with margin-bottom: 20px followed by one with margin-top: 30px ends up with 30px of space between them, not 50px.

  • Collapsing only happens for vertical margins (top/bottom), never horizontal.
  • It only happens between block boxes in normal flow — flex items, grid items, and floated/absolutely positioned elements never collapse.
  • A parent and its first/last child can collapse "through" each other if there's no padding, border, or content separating them — a surprising source of a container appearing to ignore its child's top margin.
Fix for parent/child collapsing

Give the parent padding-top: 1px, a border, or set display: flow-root to establish a new block formatting context and stop the collapse.

Overflow

ValueBehavior
visible (default)Content spills outside the box, unclipped
hiddenClipped, no scrollbar, not reachable by keyboard/scroll
scrollAlways shows a scrollbar, even if content fits
autoScrollbar appears only when content overflows
clipLike hidden, but also disallows programmatic scrolling

overflow-x and overflow-y let you set each axis independently — a common pattern is overflow-x: auto; overflow-y: hidden; for a horizontal scroll rail.

display & the outer/inner model

Modern CSS treats display as two values: an outer display type (how the box interacts with siblings — block or inline) and an inner display type (how it lays out its own children — flow, flex, grid).

display.css
display: block;         /* takes full width, stacks vertically, accepts width/height */
display: inline;        /* flows with text, ignores width/height, top/bottom margin */
display: inline-block;  /* flows inline but respects width/height/margin fully */
display: flex;          /* outer: block, inner: flex — children become flex items */
display: inline flex;   /* two-value syntax: outer inline, inner flex */
Interview angle

Q: A 3-column layout using percentage widths keeps wrapping to a 4th row — why? Almost always box-sizing: content-box plus padding pushing the true rendered width past 100%. Ask about margin collapsing next — it trips up nearly every candidate on a whiteboard. More in the interview guide.

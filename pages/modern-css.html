Native nesting

CSS now supports nesting selectors without a preprocessor. Nested rules need the & placeholder when combining with the parent (like Sass), except when the nested selector already starts with a combinator or compound selector, where it is implied.

nesting.css
.card {
  padding: 1.5rem;

  &:hover { border-color: var(--brand); }

  h3 {
    margin: 0 0 0.5rem;
  }

  @media (min-width: 600px) {
    padding: 2rem; /* media queries can nest too */
  }
}

Cascade layers - @layer

Layers let you group rules into named buckets whose priority is decided by declaration order of the layers themselves, before specificity is even considered - a way to guarantee, say, that all component styles beat all reset styles regardless of how specific a reset selector is.

layers.css
/* declare the priority order once, up front */
@layer reset, base, components, utilities;

@layer reset {
  * { margin: 0; }
}
@layer components {
  .card { margin-bottom: 1rem; } /* wins over reset even though reset uses * */
}
Unlayered styles always win

Any CSS not inside a layer is treated as the highest-priority layer, above every named layer - useful for one-off overrides, but a reminder that layers only help you order code you deliberately opted in.

:has() as a parent selector

Covered in depth in selectors & specificity - it's worth calling out here because it's arguably the single most-requested CSS feature of the last decade, letting you style an element based on its descendants or following siblings.

has-forms.css
/* style a form label when its input is focused, no JS needed */
label:has(+ input:focus) { color: var(--brand); }

Container queries, recap

See the full breakdown in responsive design - container queries are consistently grouped under "modern CSS" in interviews because they shifted responsive design from a page-level concern to a component-level one.

Scroll-driven animation

Animations can now be timed against scroll position instead of wall-clock time, without a scroll event listener in JavaScript:

scroll-animation.css
.progress-bar {
  animation: grow linear;
  animation-timeline: scroll(root); /* driven by page scroll, not time */
}
@keyframes grow {
  from { transform: scaleX(0); }
  to   { transform: scaleX(1); }
}

Interview angle

Q: Explain @layer to someone who thinks specificity already solves this. Specificity is per-selector and can't express "everything in this whole group of rules should lose to everything in that group," regardless of selector complexity - layers solve an architectural problem specificity was never designed for.

Custom properties

Declaring & using

variables.css
:root {
  --brand: #7aa2f7;
  --space-md: 1rem;
  --radius: 10px;
}

.button {
  background: var(--brand);
  padding: var(--space-md);
  border-radius: var(--radius);
}

Custom property names are case-sensitive and must start with two dashes. Unlike Sass variables, they're real values the browser resolves at render time — they participate in the cascade and can be changed live via JavaScript or media queries.

Cascade & scope

A custom property declared on any selector is scoped to that element and inherits down to its descendants — it's not global unless declared on :root (the <html> element). This means you can redefine the same variable name at different points in the tree:

scoped-variables.css
:root        { --gap: 16px; }
.compact     { --gap: 8px; } /* overridden inside .compact and its children */
.stack       { gap: var(--gap); }

Fallback values

fallbacks.css
color: var(--text-color, #1a1a1a); /* used if --text-color is unset */

The fallback only kicks in if the variable is unset — if it's set to an invalid value for that property, the property falls back to its own initial value or inherited value instead (this is called "computed value time" invalidation), not to your fallback string.

Theming with variables

theming.css
:root {
  --bg: #ffffff;
  --fg: #111111;
}
[data-theme="dark"] {
  --bg: #0b0e14;
  --fg: #e8eaed;
}
body { background: var(--bg); color: var(--fg); }

Toggle the theme by flipping data-theme on <html> in JS — no stylesheet swap, no flash, and the whole tree updates because every color derives from these two variables.

@property — typed custom properties

Plain custom properties are untyped strings, which means the browser can't animate them (it doesn't know how to interpolate between two arbitrary strings). @property registers a variable with a real syntax and default, making it animatable:

at-property.css
@property --angle {
  syntax: "<angle>";
  inherits: false;
  initial-value: 0deg;
}
.spinner {
  background: conic-gradient(from var(--angle), #7aa2f7, transparent);
  transition: --angle 0.6s ease; /* now this actually animates smoothly */
}
.spinner:hover { --angle: 360deg; }

Reading/writing from JS

interop.js
// read a computed custom property
const brand = getComputedStyle(document.documentElement)
  .getPropertyValue('--brand').trim();

// write one — every consumer updates instantly
document.documentElement.style.setProperty('--brand', '#e0af68');
Interview angle

Q: CSS variables vs Sass variables — what's the real difference? Sass variables are compile-time text substitution and gone by the time CSS ships; custom properties are live in the browser, inherit through the DOM, can be scoped per-element, changed by media queries or JS, and read at render time.

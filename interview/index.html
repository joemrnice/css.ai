CSS interview questions & answers

Real questions grouped by level, with plain-English answers and the follow-up angle an interviewer is likely to probe next. Filter by level or topic, or just scroll.

A class (.name) can be reused on many elements and has lower specificity; an ID (#name) must be unique per page and has much higher specificity, making it harder to override later. Prefer classes for styling.

Cascading. It describes how the browser resolves conflicting rules for the same element and property using origin, layers, specificity, and source order, in that priority. It's not just a name - it's the whole conflict-resolution model.

Every element is a box made of content, padding, border, and margin, from the inside out. width/height size the content by default; box-sizing: border-box changes that so width includes padding and border too.

With content-box (the default), padding and border add to the element's set width. With border-box, padding and border are included inside that width, so the box stays exactly the size you specified.

Block elements take the full available width and stack vertically. Inline elements flow with text, ignore width/height, and only respect horizontal margin/padding visually. Inline-block flows inline but fully respects width, height, and vertical margin/padding.

static (default, normal flow), relative (offset from its normal position, stays in flow), absolute (removed from flow, positioned against the nearest positioned ancestor), fixed (positioned against the viewport), and sticky (relative until a scroll threshold, then fixed within its parent).

.parent > .child selects direct children only. .parent .child (a space) selects descendants at any depth.

Make the parent a flex container and set display: flex; align-items: center; justify-content: center; — the most common modern answer. Grid's place-items: center is an equally valid one-liner.

em is relative to the font-size of the element itself (or its parent, for font-size), so it can compound unpredictably when nested. rem is always relative to the root <html> font-size, which makes it more predictable for consistent spacing and type scales.

Certain properties, mostly text-related ones like color and font-family, automatically pass their computed value down to child elements unless a more specific rule overrides them. Box-model properties like margin and width do not inherit.

Hex (#7aa2f7), functional notation like rgb()/hsl()/oklch(), and named colors like CornflowerBlue. Modern syntax also supports an alpha channel directly, e.g. rgb(0 0 0 / 50%).

display: none removes the element from layout entirely - it takes up no space and isn't announced by screen readers. visibility: hidden hides it visually but keeps its layout space reserved.

Shorthand for flex-grow: 1; flex-shrink: 1; flex-basis: 0% - the item ignores its natural content size and grows to fill available space, sharing it proportionally with sibling items that also have flex: 1.

A conditional block of CSS that only applies when a condition about the browsing environment is true - most commonly viewport width, e.g. @media (min-width: 768px) { ... }.

It matches every element on the page. It's commonly used for resets like box-sizing: border-box. It's rarely a real performance issue at typical page sizes, but combined with expensive properties or very deep DOM trees it can add measurable style recalculation cost.

As a tuple of (inline styles, ID selectors, class/attribute/pseudo-class selectors, type/pseudo-element selectors), compared left to right. It's not additive across columns - ten classes never outweigh a single ID, because the ID column is compared first.

Adjacent vertical margins between block-level, in-flow siblings collapse to the larger value instead of adding together. It doesn't happen for horizontal margins, for flex/grid items, or for floated/absolutely-positioned elements - and it can happen 'through' a parent and its first/last child if nothing separates them.

Both grow and shrink, but flex: 1 sets flex-basis to 0%, ignoring the item's content size as a starting point, so items grow purely by ratio. flex: auto sets flex-basis to auto, so it starts from the content's natural size before growing - items with more content end up larger.

Both create as many tracks as fit given a minmax() constraint. The difference shows only when there are fewer items than possible tracks: auto-fill keeps the empty tracks (items don't stretch), auto-fit collapses empty tracks to zero width and lets existing items stretch to fill the row.

z-index only compares elements within the same stacking context. If an ancestor creates its own stacking context - for example via opacity less than 1, a transform, a filter, or its own z-index - nothing inside that ancestor can render above a sibling of that ancestor, regardless of how high its own z-index is set.

:is() and :where() both match any selector in a list, shortening repetitive selectors. :is() takes on the specificity of its most specific argument; :where() always has zero specificity, useful for easily-overridable base styles. :not() excludes elements matching its argument and (in modern CSS) can take a full selector list.

Custom properties are resolved by the browser at render time - they cascade, can be scoped to any element (not just globally), inherit down the DOM, and can be read or changed via JavaScript or media queries. Sass variables are compile-time text substitution and don't exist at all once the CSS ships.

A media query responds to the viewport or device characteristics. A container query responds to the size of a specific ancestor element that's been opted in with container-type - which lets the same component adapt based on where it's placed, independent of the overall screen size.

Browsers can animate them on the compositor thread without triggering a layout recalculation or repaint on every frame, unlike properties such as width, top, or margin, which force the browser to recompute geometry each frame.

It keeps every selector a single flat class, so specificity stays uniform and predictable across a whole codebase, and it makes a class's relationship to its component explicit from the name alone (block, element, or modifier) without needing to read the CSS file.

When you need to control two dimensions at once - rows and columns together - or need explicit item placement by line number or named area. Flexbox is for distributing items along a single axis where content should influence sizing.

initial resets a property to its specification-defined default value. inherit forces it to take the parent's computed value, even for properties that don't normally inherit. unset acts like inherit for naturally-inheriting properties and like initial for everything else.

:first-child matches only if the element is literally the first child of its parent, regardless of type. :first-of-type matches the first sibling of its specific tag type, even if other different elements come before it.

It lets a nested grid inherit its parent's track sizing instead of defining its own, so independently-sized items nested inside separate grid cells - like card titles and prices - can still align to a shared set of tracks across the whole layout.

clamp(min, preferred, max) picks the preferred value but constrains it between min and max. It's most commonly used for fluid typography: font-size: clamp(1.5rem, 4vw, 3rem) scales smoothly with viewport width but never goes below or above the bounds.

min-content is the smallest size a box can be without overflowing its own content (e.g. the widest unbreakable word). max-content is the size it would be with no wrapping at all. fit-content acts like max-content but is capped by the available space, like a hybrid of the two.

Cascade layers let you group rules into named buckets whose priority is decided purely by declaration order of the layers - before specificity is even evaluated. Specificity is a per-selector comparison and can't express a rule like 'everything in this whole group of rules should lose to everything in that group,' regardless of how specific individual selectors are within each group. Layers add an entirely new axis to the cascade above specificity.

Look for repeated read-then-write cycles that alternate between reading a layout-dependent property (like offsetHeight) and writing a style that invalidates layout, forcing a synchronous reflow on every iteration. The fix is usually batching all reads before all writes, and preferring transform/opacity-driven animation over properties that trigger layout, ideally verified with the browser's performance/rendering panel.

The root element; any positioned element (position other than static) with a z-index other than auto; flex/grid items with a z-index other than auto; elements with opacity less than 1; elements with a transform, filter, backdrop-filter, perspective, clip-path, mask, or will-change naming one of these; elements with isolation: isolate; and elements with mix-blend-mode other than normal. Recognizing this list is often the difference between guessing and diagnosing a z-index bug quickly.

A strong answer names concrete mechanisms, not just a methodology label: cascade layers or ITCSS-style load order to make specificity fights structurally impossible, a component-scoping convention (BEM or CSS Modules) so class collisions can't happen, design tokens as custom properties for anything visual, and a lint rule capping selector specificity/nesting depth in CI.

Layout (geometry: position and size) is the most expensive and cascades to affected siblings/ancestors. Paint (turning boxes into pixels: color, shadows, borders) is cheaper but still per-frame work. Composite (assembling pre-painted layers, transform/opacity changes) is the cheapest and can run on a separate thread. Choosing transform/opacity for animation keeps work in the compositor stage entirely.

Untyped custom properties are just strings to the browser - it has no way to interpolate between two arbitrary strings the way it can interpolate a number or color. @property registers a variable with a real syntax (like or ) and an initial value, which gives the browser enough type information to compute intermediate values during a transition or animation.

In rough order of preference: wrap your styles in a later-declared cascade layer so they win regardless of the third party's specificity; increase actual selector specificity deliberately rather than reaching for !important; use :where() to keep your own base styles at zero specificity so they don't compound the problem; and only as a last resort, scope with a shadow DOM or an iframe if true isolation is required.

Container queries keep responsiveness inside CSS and require no JavaScript or extra props, and they respond to actual rendered space rather than an assumption about where a component will be used. The trade-off is a slight performance cost from the browser tracking containment, and that very deeply nested conditional variants can become harder to trace than an explicit prop-driven variant would be in code review.

:not() and :is() both contribute the specificity of their single most specific argument to the overall selector, not the sum of all arguments and not zero. :where() is the exception - it always contributes zero specificity regardless of what's inside it, which makes it useful for writing overridable defaults.

The unitless value 1.5 is a multiplier of the element's own font-size and inherits as that multiplier - child elements recompute it against their own font-size. A fixed 24px inherits as a literal pixel value, which can look wrong if a child has a different font-size. Unitless is almost always the safer default.

The adjacent sibling combinator - it selects an element that comes immediately after another specific element, sharing the same parent. h2 + p selects a paragraph only if it directly follows an h2.

A fraction of the leftover space in the grid container after fixed-size tracks and gaps are subtracted - not a fraction of the total container width.

With the ::placeholder pseudo-element: input::placeholder { color: #999; }.

hidden clips overflowing content with no scrollbar. scroll always shows a scrollbar even if content fits. auto shows a scrollbar only when content actually overflows.

Browsers ship inconsistent default styles for elements like margins on headings or list bullet styles. A reset strips these to a blank baseline; a normalize approach instead makes defaults consistent across browsers without removing them entirely.

Allows flex items to move onto multiple lines when they don't fit on one, instead of shrinking indefinitely or overflowing the container (the default, nowrap, keeps everything on a single line).

It tells the browser to render text immediately using a fallback font, then swap to the custom web font once it finishes loading, rather than leaving text invisible while the font downloads (the default 'block' behavior in many cases).

It keeps the animation's first-keyframe styles applied before it starts and its last-keyframe styles applied after it ends. Without it, an element can flash in its un-animated state right before the animation begins, or snap back to that state right after it finishes.

@import dumped every variable, mixin, and function into one shared global namespace, which caused collisions across a large project. @use namespaces everything by the file it came from, so two partials can define a variable with the same name without conflict.

Utility-first avoids ever inventing component names and ships less unused CSS, since a build step purges classes you didn't actually use - but markup becomes more verbose and visually noisy, and consistency depends on disciplined use of the design token config rather than being enforced by the CSS structure itself.

hsl() is not perceptually uniform - lowering lightness by the same amount looks like a bigger change on some hues than others, especially blues versus yellows. oklch() is built so equal numeric steps in lightness look like equal visual steps, which makes programmatically generating a consistent tint/shade scale far more reliable.

It lets you select a parent or preceding element based on what's inside or after it - effectively a parent selector, which CSS lacked for its entire history. A common case: styling a form field wrapper differently only when it contains an invalid input, with no JavaScript.

:focus shows an outline for every focus event, including mouse clicks, which many designs then strip entirely, breaking keyboard accessibility. :focus-visible only applies when the browser determines the focus should be visibly indicated - typically keyboard navigation - so you can keep a clean look for mouse users without removing indicators for keyboard users.

A plain fr track still won't shrink below its content's min-content size by default, so a long unbreakable string (like a URL) can force the whole grid wider than intended. Wrapping it in minmax(0, 1fr) allows the track to shrink all the way to zero if needed, letting overflow rules like text-overflow: ellipsis actually take effect.

If any ancestor has a transform, filter, perspective, or will-change naming one of these, that ancestor creates a new containing block, and the fixed element positions relative to it instead of the viewport - making it appear to scroll along with that ancestor.

With an @media print block, or a separate stylesheet linked with media="print". Common patterns include hiding navigation and interactive elements, forcing a light background, and controlling page breaks with break-before/break-after/break-inside.

It lets the browser skip layout, paint, and rendering work for off-screen content entirely until it's near the viewport, similar to native lazy-loading but for arbitrary DOM subtrees. The trade-off is that without an explicit contain-intrinsic-size, the browser has no size estimate for unrendered content, which can cause scrollbar jumps as content becomes visible and gets measured for the first time.

Wrap first-party overrides in a cascade layer declared after the library's layer (or after an unlayered import if the library isn't layer-aware), so they win by layer order rather than needing higher specificity selectors - avoiding an arms race of increasingly specific or !important-laden overrides.

Reading a layout-dependent property forces the browser to synchronously flush any pending style/layout changes to answer accurately. Interleaving writes (toggling display) and reads (offsetHeight) in a loop forces a full synchronous reflow on every iteration instead of one batched reflow - this is 'layout thrashing,' and the fix is to batch all reads, then all writes.

When the parent's track sizes are dynamic or content-driven (e.g. auto-sized columns based on the widest item across the whole layout) - manually repeating a fixed value on a nested grid can't track that dynamic sizing, while subgrid inherits the actual resolved tracks from the parent, keeping nested content genuinely aligned even as sizes change.

Blending two colors, including CSS variables, directly in a chosen color space at render time - useful for deriving hover/active states or tint scales from a single brand color variable without a preprocessor's compile-time color functions, and it updates live if the source variable changes (e.g. via a theme toggle).

Extremely long, repetitive class names on deeply nested components, and no built-in mechanism for shared layout/spacing utilities, which pushes teams toward either verbose duplicate declarations or an ad hoc mix of BEM plus a small utility layer - most large teams end up formalizing that utility layer rather than pretending BEM alone is sufficient.

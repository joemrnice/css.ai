Class over ID

Reach for classes, not IDs, when styling. IDs have high specificity that's hard to override later, and an ID must be unique per page — a class can be reused freely.

Combinators

combinators.css
.card p       { /* descendant — any depth inside .card */ }
.card > p     { /* direct child only */ }
h2 + p        { /* adjacent sibling — the p immediately after h2 */ }
h2 ~ p        { /* general sibling — any p after h2, same parent */ }

The adjacent-sibling combinator (+) is the classic way to add spacing between stacked elements without a wrapper: * + * { margin-top: 1rem; } — sometimes called the "lobotomized owl" selector.

Pseudo-classes & pseudo-elements

Pseudo-classes (one colon) target elements in a particular state. Pseudo-elements (two colons, by modern convention) target a sub-part of an element that isn't in the DOM.

Pseudo-classMatches
:hover / :focus / :activeInteraction states
:first-child / :last-childPosition among siblings, any type
:nth-child(2n)Formula-based position — 2n is every even child
:not(.disabled)Excludes matches
:checked / :disabled / :requiredForm element state
:focus-visibleFocus shown only for keyboard users, not mouse clicks
pseudo-elements.css
.tooltip::before {
  content: "ⓘ";
  margin-right: 4px;
}
p::first-line { font-weight: 600; }
input::placeholder { color: #8a8f9c; }
Gotcha

::before/::after need a content property to render — even an empty string, content: "";, works and is common for decorative shapes.

Attribute selectors

attributes.css
[disabled]              { /* has the attribute, any value */ }
[type="checkbox"]       { /* exact match */ }
[class~="tag"]          { /* one word in a space-separated list */ }
[href^="https"]         { /* starts with */ }
[href$=".pdf"]          { /* ends with */ }
[href*="docs"]          { /* contains, anywhere */ }

:is(), :where(), and :has()

:is() and :where() both accept a selector list and match any of them — they exist to shorten repetitive selectors:

is-where.css
/* instead of repeating the descendant combinator four times */
:is(article, aside, section, nav) h2 {
  margin-top: 0;
}

The difference: :is() takes on the specificity of its most specific argument; :where() always has zero specificity, which makes it ideal for base/reset styles you want to stay trivially overridable.

:has() is the "parent selector" CSS lacked for years — it matches an element based on what's inside it:

has.css
/* style a form field wrapper only when it contains an invalid input */
.field:has(input:invalid) {
  border-color: #f7768e;
}
/* a card that has an image gets different padding than one that doesn't */
.card:has(img) { padding-top: 0; }

Specificity, step by step

Specificity is scored as a tuple (inline, IDs, classes/attributes/pseudo-classes, types/pseudo-elements). Compare left to right — the first column that differs decides the winner. It is not a base-10 score, so ten classes never beat one ID.

Selector(id, class, type)
div(0, 0, 1)
.card(0, 1, 0)
.card.featured(0, 2, 0)
#hero(1, 0, 0)
nav ul li a.active(0, 1, 3)

Interview angle

Q: Which wins — #nav .active or .nav-item.active.current? The ID selector wins regardless of how many classes are stacked on the other side, because IDs are compared before classes. Full answer in the interview guide.
